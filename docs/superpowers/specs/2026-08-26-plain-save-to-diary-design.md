# 録音タブの「そのまま保存」ボタン 設計

- 日付: 2026-08-26
- 対象: 思考整理（voice-memo PWA）
- 状態: 設計確定待ち

## 背景と目的

録音タブのキーボード入力カードには現在「整理する」しかなく、押すと必ず AI が走る。

現状の「整理する」の実際の動きは次のとおり（確認済み）:

1. `/api/organize` で AI がメモを整理し、メモを1件作る
2. `organize()` の中で `autoSaveDiary(memo)` が呼ばれ、日記にも1件入る
3. `autoSaveDiary()` がさらに `/api/diary` を呼び、AI が日記文を整形して差し替える

**つまり1回の「整理する」で AI 呼び出しが2回発生する。**

書き殴って残したいだけのときにこれは重い。AI を一切通さず、入力したテキストをそのまま日記に落とすだけのボタンを足す。

## 方式

キーボード入力カードのボタン列に「そのまま保存」を1つ追加し、押したら日記に1件保存して終わる。AI は呼ばない。メモは作らない。

**録音（マイク）の流れは変更しない。** 録音した場合は従来どおり文字起こし後に自動で整理される。書き殴りたい場合はキーボード入力カードを開き、その中の「🎤 音声入力」（ブラウザ内蔵の音声認識。AI を使わないので無料）で喋ってから「そのまま保存」を押す。

### 検討したが採らなかった案

| 案 | 不採用の理由 |
|---|---|
| 録音後に「整理する / そのまま保存」を選ばせる | 録音の主用途は整理させることなので、毎回1タップ増えるのは割に合わない。「録音したら勝手に整理される」という既存の流れも壊れる |
| 録音前にモードをトグルで選ばせる | タップは増えないが、切り替え忘れると意図しない方に保存され、しかも気づきにくい |
| 保存時にタイトルを自動生成する | AI で付けるとこの機能の意味（無料・即時）が消える。先頭行の切り出しは書き殴りだと不自然な見出しになりやすい |

## スコープ

### やること

- キーボード入力カードに「そのまま保存」ボタンを追加する
- 押したら入力テキストをそのまま日記に1件保存する
- 日記保存処理を共通関数に切り出し、日記タブの「保存」と共用する

### やらないこと

- 録音（マイク）の流れの変更
- タイトルの自動生成
- メモの作成（タスク・買い物などの抽出）
- 保存した日記の Obsidian への自動送信（日記タブのボタンから手動で送れる）

## UI 変更

`public/index.html` のキーボード入力カード（`id="textCard"`）のボタン列に1つ追加する。

変更前:

```
[🎤 音声入力] [整理する] [閉じる]
```

変更後:

```
[🎤 音声入力] [整理する] [そのまま保存] [閉じる]
```

- 「整理する」は従来どおり `pill-btn primary`（塗り）のまま
- 「そのまま保存」は `pill-btn`（塗りなし）にする。**AI を使う方と使わない方を見た目で区別し、押し間違いを防ぐため**
- ボタン ID は `plainSaveBtn`

`.text-actions` は既に `flex-wrap: wrap`（`style.css:1761-1765`）なので、4つ目を足しても狭い画面で折り返す。**CSS の変更は不要。**

## 動作

`plainSaveBtn` の click で次を行う。

1. `stopDictation()` を呼ぶ（音声入力中なら止める。「整理する」と同じ）
2. `textInput.value` を `trim()` する
3. 空なら `toast('テキストを入力してください')` して終了（「整理する」と同じ文言）
4. 日記に1件保存する（後述の共通関数を使う）
5. `textInput.value = ''`、`textCard` に `hidden` を付けて閉じる（「整理する」の成功時と同じ）
6. `renderDiaryView()` を呼ぶ
7. `toast('📔 日記に保存しました')`

手順6について: 日記タブは切り替えのたびに再描画されるため厳密には省略できるが、日記タブ側の保存ハンドラも保存後に `renderDiaryView()` を呼んでおり、揃えておく方が後から読んだときに分かりやすい。コストも無視できる。

保存される日記エントリ:

| 項目 | 値 |
|---|---|
| `date` | `diaryDateStr()`（今日のローカル日付） |
| `title` | `''`（空） |
| `text` | 入力テキスト（trim 済み） |
| `formatted` | `text` と同じ |
| `highlights` | `[]` |

`title` が空でも日記タブの表示は日付だけ出す作りになっているため問題ない。タイトルを付けたくなった場合は日記タブで編集する。

## 共通関数への切り出し

日記タブの「保存」ボタン（`initDiaryEditor()` 内の `saveBtn` ハンドラ）が既に同じ形のエントリを作っている。同じ処理が2箇所にあると片方だけ直して食い違うので、共通関数に切り出す。

```
addDiaryEntry(text, title, date) -> entry
```

- `diaries.unshift(entry)` して `saveDiaries()` まで行い、作ったエントリを返す
- `title` 省略時は `''`、`date` 省略時は `diaryDateStr()`
- `id` は `'diy_' + Date.now()`、`ts` は `Date.now()`、`formatted` は `text`、`highlights` は `[]`
- **画面の再描画やトーストは呼び出し側の責任**とする（日記タブと録音タブで後処理が違うため）
- **入力が空かどうかの検証は行わない。** 呼び出し側が済ませている前提とする。ここで検証を足すと日記タブ側の既存の挙動（`toast('内容を入力してください')`）と二重になる

日記タブの `saveBtn` ハンドラをこの関数を使う形に書き換える。**日記タブの挙動は一切変えない。**

`autoSaveDiary()` は `memoId` や AI 整形の後処理を持つ別物なので、この共通化の対象にしない。

## エラー処理

| 状況 | 挙動 |
|---|---|
| 入力が空 | `toast('テキストを入力してください')`、保存しない、カードも閉じない |
| localStorage の保存に失敗 | 既存の `persist()` 経由で `saveDiaries()` が警告トーストを出す。この機能では追加の処理をしない |

AI を呼ばないため、通信エラーの経路は存在しない。

## 検証方法

自動テストは置かない（テスト基盤がなく、既存タスクと同じ方針）。ブラウザ上のコンソール評価で確認する。

1. キーボード入力カードに4つのボタンが出ること。並びが `🎤 音声入力 / 整理する / そのまま保存 / 閉じる` であること
2. 「整理する」だけが `primary` クラスを持つこと
3. テキストを入れて「そのまま保存」を押すと、日記が1件増え、`text` と `formatted` が入力どおり、`title` が空、`date` が今日であること
4. 保存後に入力欄が空になり、カードが閉じること
5. **AI が呼ばれないこと**（`/api/organize` と `/api/diary` へのリクエストが発生しないこと）
6. 空のまま押すと保存されず、カードも閉じないこと
7. メモが増えていないこと（`voiceMemos.v1` が変化しないこと）
8. 日記タブの「保存」が従来どおり動くこと（**共通化による回帰がないこと**）
9. 375px 幅でボタン行が折り返し、はみ出さないこと

## 未確定事項と既定値

| 項目 | 既定 | 変更が必要になる条件 |
|---|---|---|
| ボタンの文言 | `そのまま保存` | 分かりにくい場合 |

| タイトル | 常に空 | 自動生成が欲しくなった場合 |
