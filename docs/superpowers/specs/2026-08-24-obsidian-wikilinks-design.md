# Obsidian ウィキリンク自動付与 設計

- 日付: 2026-08-24
- 対象: 思考整理（voice-memo PWA）
- 前提: `2026-08-24-obsidian-daily-note-integration-design.md`（v53 で実装済み）の拡張
- 状態: 設計確定待ち

## 背景と目的

Obsidian の価値は `[[ウィキリンク]]` でノート同士が繋がり、グラフとして育つことにある。現状の連携はプレーンな Markdown を送るだけで、リンクが一切ない。

メモに出てくる人名・案件名などを自動で `[[...]]` にして、日々の音声メモが Obsidian 上で勝手に繋がっていく状態を作る。

**vault の中身は読めない**（前提設計どおり `obsidian://` URI で送るだけで、ファイルアクセス手段を持たない）。ただし Obsidian は存在しないノートへのリンクを未解決リンクとしてグラフに表示し、クリック時に作成するため、リンク先の実在を知る必要はない。

## 方式

Markdown を組み立てる時点（`memoToMarkdown()`）で、本文中の該当語を `[[語]]` に置換する。**メモのデータ自体は書き換えない。** 送信のたびに組み立て直すので、後から登録語を増やせば古いメモを送るときにも新しい登録語が効く。

リンク対象は2系統。

| 系統 | 出所 | 適用範囲 | AI |
|---|---|---|---|
| 登録語 | 設定画面でユーザーが1行1語で登録 | 全メモ（古いメモも含む） | 使わない |
| AI抽出語 | `/api/organize` の応答に含まれる `entities` | 新しく整理したメモのみ | 既存の呼び出しに相乗り |

AI抽出は既存の `/api/organize` / `/api/append` の応答スキーマを拡張して相乗りさせる。**AI呼び出しの回数は増えない**（出力が数十トークン伸びるだけ）。既に保存済みのメモには `entities` がないため、そこには登録語だけが効く。

### 検討したが採らなかった案

| 案 | 不採用の理由 |
|---|---|
| 送信のたびに専用のAI呼び出しで抽出 | 全メモに均一に効くが、1送信ごとに費用が増える。利用者がコストを避ける判断をした |
| 既存メモの一括バックフィル | 作るものが最も多い。まず新規メモで運用してみて、必要になってから足す方が確実 |
| 末尾に「関連: [[A]] [[B]]」とまとめる | 本文を壊さない利点はあるが、リンクが文脈から切り離される。利用者がインラインを選択 |

## リンク化のルール

**適用対象**: 要約（summary）と各項目のテキスト（item.text）。

**見出しは対象外。** `## 14:32 会議の準備` の部分にはリンクを付けない。見出しを予測可能に保つため。

### 置換ルール

1. **1回の呼び出しにつき、各語の最初の1回だけ**置換する。同じ語が同じ文字列に3回出ても、リンクは1つ。
   - `applyWikiLinks(text, terms)` は「1つの文字列」を受け取る。呼び出し側は要約と各項目テキストを**別々に**渡す。したがって同じ語が要約と項目の両方に出れば、両方リンクになる（これは意図した挙動で、利用者に提示した例のとおり）。
2. **長い語を優先する。** 「ABC」と「ABCプロジェクト」が両方リンク対象なら `[[ABCプロジェクト]]` を選ぶ。候補語を文字数の降順にソートしてから順に処理する。
3. **既にリンクの中にある語は二重にリンクしない。** 置換済みの `[[...]]` の内側にはマッチさせない。
4. **リンク記法を壊す語は除外する。** `[` `]` `|` `#` `^` のいずれかを含む語、および空文字・空白のみの語はリンク化しない。
5. 大文字小文字は区別する（Obsidian のリンク解決に合わせる）。日本語主体なので実害は薄い。

置換は単純な部分文字列マッチとする。日本語には単語境界がなく、形態素解析を持ち込むのは過剰。

## AI抽出語（entities）

### 応答スキーマの拡張

`server.js` の `JSON_FORMAT_SPEC` に `entities` を追加する。この定数は `/api/organize` と `/api/append` の両方が使うため、両エンドポイントに同時に反映される。

```json
"entities": ["田中さん", "ABCプロジェクト"]
```

指示文に加える制約:

- **固有名詞のみ。** 人名・組織名・案件名/プロジェクト名・場所名・製品名。
- 「牛乳」「会議」「資料」のような一般名詞は入れない。
- **最大5語。**
- 語は本文に現れる表記そのままで返す（置換に使うため）。

### パーサの更新

`server.js` の `parseOrganized()` は返すフィールドを許可リストで絞っている（`title` / `summary` / `workspace` / `categories`）。ここに `entities` を通す処理を足さないと、AI が返しても捨てられる。

正規化: 配列でなければ空配列。各要素を文字列化して `trim()`、空を除去、40文字を超えるものを除去、重複を除去、先頭5件に切り詰め。

### 表記ゆれ対策

同じ人物が `[[田中さん]]` と `[[田中]]` に分裂するとグラフが割れる。

対策として、クライアントが**これまでに使ったリンク語の一覧**をリクエストに含め、プロンプトで「この一覧に該当する語があれば、一覧の表記をそのまま使うこと」と指示する。

- リクエストボディに `vocab: string[]` を追加（`/api/organize` と `/api/append` の両方）
- サーバは受け取った `vocab` を文字列化・`trim()` し、**先頭100語**に切り詰めてプロンプトに埋め込む（プロンプト肥大の防止）
- `vocab` が空なら、その指示文ごと省く

語彙はクライアント側で**保存せずに毎回算出する**（`getLinkVocabulary()`）。出所は「登録語」＋「全メモの `organized.entities`」。単一の出所から導出するので、別途保存して実体とズレる事故が起きない。

並び順は **登録語が先、その後にメモの `entities` を新しい順**（`memos` の先頭が最新）。登録語はユーザーの明示的な意思なので、100語の上限で truncate されるときに真っ先に残す必要がある。重複を除いたうえで100語で打ち切る。

## データモデルの変更

| 場所 | キー / フィールド | 型 | 用途 |
|---|---|---|---|
| メモ | `memo.organized.entities` | `string[]` | AI抽出語。既存メモには存在しない（`undefined` を許容すること） |
| localStorage | `voiceMemoLinkWords` | `string[]` | ユーザーが登録した語 |

語彙リストは導出値なので保存しない。

## UI 変更

### 設定画面

既存の「Obsidian連携」カード内に、vault 名の欄の下へ追加する。新しいカードは作らない。

- `<textarea>` 1つ: 1行1語で登録語を入力
- 保存ボタン（既存の vault 欄と同じ体裁）
- 保存時に空行と前後空白を落とし、重複を除く
- 登録件数を状態表示する（例: `✓ 12語を登録中`）

### メモカード

**変更なし。** 「🔮 Obsidian」ボタンの挙動が変わるだけで、見た目は同じ。

## バックアップ

書き出し形式を **v4** に上げ、`linkWords` を含める。読み込み時はメモ・日記と同じくマージ（重複語はスキップ）。

`entities` はメモの中に入っているので、メモを復元すれば一緒に戻る。追加の対応は不要。

## エラー処理

| 状況 | 挙動 |
|---|---|
| AI が `entities` を返さない / 壊れた形で返す | `parseOrganized()` が空配列に正規化。リンクは登録語だけになる。エラーは出さない |
| 登録語が0件かつ `entities` もない | 置換は何も起きず、現状どおりのプレーンな Markdown が送られる |
| リンク記法を壊す文字を含む語 | その語だけ黙って対象外にする。他の語の処理は続ける |

リンク付与は「あれば嬉しい」機能であり、失敗しても送信自体は必ず成功させる。リンク処理で例外を投げて送信を止めてはならない。

## 検証方法

自動テストは置かない（テスト基盤がなく、既存タスクと同じ方針）。ブラウザ上のコンソール評価で確認する。

`applyWikiLinks()` は純粋関数なので単体で完全に検証できる。最低限、次を確認する。

1. 単純な置換: `applyWikiLinks('田中さんと会議', ['田中さん'])` → `'[[田中さん]]と会議'`
2. 1行1回: `applyWikiLinks('田中さんと田中さん', ['田中さん'])` → `'[[田中さん]]と田中さん'`
3. 長い語優先: `applyWikiLinks('ABCプロジェクトの件', ['ABC', 'ABCプロジェクト'])` → `'[[ABCプロジェクト]]の件'`
4. 二重リンク防止: `applyWikiLinks('[[田中さん]]と会議', ['田中さん'])` → 変化なし
5. 危険な文字を含む語の除外: `applyWikiLinks('a|b の件', ['a|b'])` → 変化なし
6. 対象語なし: `applyWikiLinks('ふつうの文', [])` → 変化なし
7. `memoToMarkdown()` 全体で、見出しにリンクが付かず、要約と項目には付くこと

実機（Android）では、送ったノートで Obsidian のリンクが実際に解決し、グラフに現れることを確認する。

## 未確定事項と既定値

| 項目 | 既定 | 変更が必要になる条件 |
|---|---|---|
| AI抽出語の上限 | 5語/メモ | ノイズが多い、または足りない場合 |
| 語彙リストの上限 | 100語 | プロンプトが重い、または表記ゆれが直らない場合 |
| 除外語リスト | 作らない | AI が繰り返し不要な語を拾う場合に追加する |
